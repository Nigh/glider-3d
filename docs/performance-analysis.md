# 性能测量与优化证据

## 测试环境与方法

当前工作站为 Linux x64，Intel Core Ultra 7 265K。浏览器 Chromium 156.0.8078.4，headless，视口1440×1000、DPR 1。WebGL renderer 为 ANGLE / Vulkan SwiftShader（软件渲染），不是手机GPU。

独立rAF采样保留每一帧原始间隔，未丢弃慢帧。物理与几何时间来自游戏实际执行处；CPU渲染提交耗时不代表GPU执行耗时。基于开发服务运行，包含开发构建开销。真实Android连接检查发现设备列表为空，详见 `device-validation.md`。

## 首轮瓶颈

原始数据：`performance-before.json`。默认各短场景4秒、长场景12秒，不含页面加载和预热时间。

| 场景 | 平均FPS | P95 ms | P99 ms |
|---|---:|---:|---:|
| 默认飞机飞行 | 53.0 | 33.3 | 33.4 |
| 最大翼展飞行 | 58.5 | 16.8 | 33.3 |
| 连续轨道相机 | 40.0 | 33.4 | 50.0 |
| 连续拖翼 | 25.4 | 83.3 | 83.4 |
| 反复进入退出飞行 | 41.3 | 33.4 | 83.3 |
| 反复创建销毁几何 | 25.9 | 83.3 | 83.4 |
| 飞行与重置 | 55.3 | 33.3 | 33.4 |

代码中每次编辑释放全部机体材质再创建，丢失已编译shader，并重复设置画布尺寸。这些工作与实际几何修改没有必要的一一对应。

修复：材质、常量驾驶员几何及机体网格持久复用；每个渲染帧合并更新，只重建变化翼面；移除编辑时无变化的resize和全场景内存遍历；Auto从Low起步。驾驶员的视觉位移直接跟随物理重心，而不是仅移动整个模型。

## 第二轮定位最差帧

原始数据：`performance-intermediate.json`。各短场景6秒，长场景60秒，重置间隔15秒。默认飞行60.0FPS，拖翼57.0FPS，长场景59.7FPS；但长场景存在166.7ms最差帧。

累计原始帧间隔，166.7ms慢帧发生在采样第12549.4ms；首次Medium档采样发生在12550.0ms，shader program数从6增至13。自动升档开启阴影造成实时shader编译尖峰，与该慢帧时间吻合。

修复：Auto档始终不切换阴影，只调整DPR和远景细节；手动Medium/High仍可启用阴影。DPR不变时不重新分配画布尺寸。不通过过滤帧、缩短采样或虚报GPU耗时改善指标。

最终原始数据由相同七场景工具写入 `performance-results.json`。文件包含环境、操作次数、帧间隔、资源计数、JS堆信息和异常列表。普通手机60FPS仍需真机验证；软件渲染桌面结果不能替代该验收。

一次最终复测在页面完整 `load` 等待阶段超过10秒，尚未进入任何采样场景。工具改为等待 `DOMContentLoaded`，随后仍等待真实“开始设计”按钮与 `window.glider.state === 'design'`，再进行预热和采样；未延长或屏蔽飞行中的慢帧。导航失败不作为性能数据。

## 最终实测

各短场景6秒，长场景60秒，全部场景无未捕获页面异常。最终原始数据：`performance-results.json`。以下单位为实际rAF帧间隔，不是模拟步长。

| 场景 | 平均FPS | 平均帧间隔 ms | P95 ms | P99 ms | 最差帧 ms |
|---|---:|---:|---:|---:|---:|
| 默认飞机飞行 | 60.0 | 16.67 | 16.8 | 16.8 | 16.8 |
| 最大翼展24m飞行 | 60.0 | 16.67 | 16.8 | 16.8 | 16.8 |
| 连续轨道相机 | 59.0 | 16.95 | 16.8 | 33.3 | 33.4 |
| 连续拖翼 | 56.5 | 17.70 | 33.3 | 33.4 | 33.4 |
| 反复进入退出飞行 | 58.8 | 17.00 | 16.8 | 33.3 | 33.4 |
| 反复创建销毁几何 | 57.7 | 17.34 | 16.8 | 33.3 | 33.4 |
| 60秒飞行与重置 | 59.9 | 16.69 | 16.8 | 16.8 | 66.5 |

默认飞行采样的物理耗时平均0.044ms、最大0.200ms；CPU渲染提交平均0.328ms。连续拖翼的几何更新采样最大0.400ms，CPU渲染提交平均0.372ms。采样约每250ms进行，不能把“采样最大”当作每次调用的绝对最坏上界。

默认飞行最多79 draw calls、3111三角形；连续拖翼46 draw calls、2947三角形。反复替换几何场景的已上传geometry数保持21、texture数保持1、program数保持6，未在该场景看到资源计数持续增长。60秒场景因画质、远景和水花变化，geometry为22–26、texture保持15、program为6–11；这不等于完整的显存或泄漏证明。

最差长场景帧从中间版本的166.7ms降到66.5ms，但仍有孤立慢帧；连续拖翼也不是锁定60FPS。因此不宣称所有场景零掉帧，更不宣称普通手机60FPS已通过。真实手机硬件、热降频、Safari、长达数分钟的稳定性与GPU执行时长均未验收。

最终场景实际完成150次相机指针移动、109次翼面拖动事件、15次进入/退出飞行、61次模型替换、60秒场景5次重置。全部场景 `hiddenFrames=0`，结束时页面均为visible；错误列表为空。JS堆增量字段在本环境均为0，不能据此推断没有分配或没有GC。
