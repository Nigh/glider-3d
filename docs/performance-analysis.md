# 性能测量与优化证据

本文保留历史优化与测量证据，不作为当前性能承诺。当前仅支持桌面浏览器，移动端测试已取消。

## 测试环境与方法

本记录的采样工作站为Linux x64，Intel Core Ultra 7 265K。浏览器Chromium 156.0.8078.4，headless，视口1440×1000、DPR 1。WebGL renderer为ANGLE / Vulkan SwiftShader（软件渲染）；这些数据不代表手机GPU性能。

独立rAF采样保留每一帧原始间隔，未丢弃慢帧。物理与几何时间来自游戏实际执行处；CPU渲染提交耗时不代表GPU执行耗时。基于开发服务运行，包含开发构建开销。真实Android连接检查发现设备列表为空，详见 `device-validation.md`。

## 首轮瓶颈

原始数据：`performance-before.json`。默认各短场景4秒、长场景12秒，不含页面加载和预热时间。

| 场景 | 平均FPS | P95 ms | P99 ms |
|---|---:|---:|---:|
| 默认飞机飞行 | 53.0 | 33.3 | 33.4 |
| 最大翼展飞行 | 58.5 | 16.8 | 33.3 |
| 连续轨道相机 | 40.0 | 33.4 | 50.0 |
| 连续拖翼 | 25.4 | 83.3 | 83.4 |
| 反复进入退出飞行 | 41.3 | 33.4 | 83.3 |
| 反复创建销毁几何 | 25.9 | 83.3 | 83.4 |
| 飞行与重置 | 55.3 | 33.3 | 33.4 |

代码中每次编辑释放全部机体材质再创建，丢失已编译shader，并重复设置画布尺寸。这些工作与实际几何修改没有必要的一一对应。

修复：材质、常量驾驶员几何及机体网格持久复用；每个渲染帧合并更新，只重建变化翼面；移除编辑时无变化的resize和全场景内存遍历；Auto从Low起步。驾驶员的视觉位移直接跟随物理重心，而不是仅移动整个模型。

## 第二轮定位最差帧

原始数据：`performance-intermediate.json`。各短场景6秒，长场景60秒，重置间隔15秒。默认飞行60.0FPS，拖翼57.0FPS，长场景59.7FPS；但长场景存在166.7ms最差帧。

累计原始帧间隔，166.7ms慢帧发生在采样第12549.4ms；首次Medium档采样发生在12550.0ms，shader program数从6增至13。自动升档开启阴影造成实时shader编译尖峰，与该慢帧时间吻合。

修复：Auto档始终不切换阴影，只调整DPR和远景细节；手动Medium/High仍可启用阴影。DPR不变时不重新分配画布尺寸。不通过过滤帧、缩短采样或虚报GPU耗时改善指标。

最终原始数据由相同七场景工具写入 `performance-results.json`。文件包含环境、操作次数、帧间隔、资源计数、JS堆信息和异常列表。历史普通手机60FPS目标未完成真机验收；当前不支持移动端，也不以软件渲染桌面结果作手机性能承诺。

一次最终复测在页面完整 `load` 等待阶段超过10秒，尚未进入任何采样场景。工具改为等待 `DOMContentLoaded`，随后仍等待真实“开始设计”按钮与 `window.glider.state === 'design'`，再进行预热和采样；未延长或屏蔽飞行中的慢帧。导航失败不作为性能数据。

## 最终实测

各短场景6秒，长场景60秒，全部场景无未捕获页面异常。最终原始数据：`performance-results.json`。以下单位为实际rAF帧间隔，不是模拟步长。

| 场景 | 平均FPS | 平均帧间隔 ms | P95 ms | P99 ms | 最差帧 ms |
|---|---:|---:|---:|---:|---:|
| 默认飞机飞行 | 60.0 | 16.67 | 16.8 | 16.8 | 16.8 |
| 最大翼展24m飞行 | 60.0 | 16.67 | 16.8 | 16.8 | 16.8 |
| 连续轨道相机 | 59.0 | 16.95 | 16.8 | 33.3 | 33.4 |
| 连续拖翼 | 56.5 | 17.70 | 33.3 | 33.4 | 33.4 |
| 反复进入退出飞行 | 58.8 | 17.00 | 16.8 | 33.3 | 33.4 |
| 反复创建销毁几何 | 57.7 | 17.34 | 16.8 | 33.3 | 33.4 |
| 60秒飞行与重置 | 59.9 | 16.69 | 16.8 | 16.8 | 66.5 |

默认飞行采样的物理耗时平均0.044ms、最大0.200ms；CPU渲染提交平均0.328ms。连续拖翼的几何更新采样最大0.400ms，CPU渲染提交平均0.372ms。采样约每250ms进行，不能把“采样最大”当作每次调用的绝对最坏上界。

默认飞行最多79 draw calls、3111三角形；连续拖翼46 draw calls、2947三角形。反复替换几何场景的已上传geometry数保持21、texture数保持1、program数保持6，未在该场景看到资源计数持续增长。60秒场景因画质、远景和水花变化，geometry为22–26、texture保持15、program为6–11；这不等于完整的显存或泄漏证明。

长场景最差帧从中间版本的166.7ms降到66.5ms；仍有孤立慢帧，连续拖翼也未锁定60FPS。真实手机硬件、热降频、Safari、数分钟稳定性与GPU执行时长均未验收。

最终场景实际完成150次相机指针移动、109次翼面拖动事件、15次进入/退出飞行、61次模型替换、60秒场景5次重置。全部场景 `hiddenFrames=0`，结束时页面均为visible；错误列表为空。JS堆增量字段在本环境均为0，不能据此推断没有分配或没有GC。

## 净空修改后的测量工具与巡航求解

性能工具使用当前三维翼端手柄、主翼安装角输入和实际“开始试飞”操作；飞行采样等待物理时间推进。每个场景独立建立浏览器上下文，完整执行固定数量的操作，记录实际采样窗口、首尾等待、长任务及模拟进度。几何耗时是最近一次飞机几何更新耗时，重复读取不表示重复执行；渲染提交耗时不代表GPU执行时间。

在 Windows x64、Ryzen 5 3600、Node 24.22.1 上，以同一双发设计和同一物理模型顺序运行巡航求解各一次。复用连续相同的稳态探针前后，完整求解结果严格相同；`sampleSteadyFlight` 调用分别为6331和4623次，耗时分别为55.24和36.69秒。这是单次串行对照，不代表所有飞机或设备的加速幅度。固定60 Hz触地对照及仍存在的耗时波动见 [contact-performance.md](contact-performance.md)。

同一台 Windows 工作站以 Chromium 156 和 SwiftShader 软件渲染，使用独立开发服务器对比 `972e8b2` 与本次修改。每个场景预热0.5秒，目标采样1秒并完成固定操作轨迹。默认飞行分别为4.7和3.9 FPS，连续拖翼为10.4和11.5 FPS，稳定风洞为12.9和13.6 FPS，风洞变角为12.3和11.8 FPS。窗口较短且软件渲染负载高，这些数字不能证明稳定性能提升，也不能代表硬件GPU性能。

同机 Node/Vite 直接调用 `controlSurfaceRegions`，每种设计预热3次并测量12次。双发预设中位耗时从17.99 ms升至27.31 ms；镜像垂翼与主翼相交的测试设计从24.83 ms升至32.71 ms。新增分离平面检查有明确成本；重复计算的减少发生在调用方，不能把单次判定称为更快。

## 扫掠包围盒解析极值

扫掠包围盒复用窄相分离平面的解析投影极值，省去逐顶点构造角度列表和重复计算三角函数。与 `ccaded0` 对照，四个预设及镜像垂翼与主翼相交的回归设计返回完全相同的净空分段。

Windows、Node 24.22.1 下直接调用 `controlSurfaceRegions`，每轮每个版本预热 5 次并采样 24 次。两轮反转版本运行顺序，中位耗时（改动前 → 改动后）分别为：双发预设 24.27 → 18.79 ms、29.54 → 21.50 ms；相交设计 29.72 → 24.49 ms、28.81 → 24.67 ms。采样期间全量单元测试在后台运行。这些数据只覆盖净空判定，浏览器场景和触地性能需独立测量。

真实浏览器触地对照使用 24 m 主翼、大滚转弱梁、固定 60 Hz 的 10 步物理输入，每步渲染一次并记录实际帧间隔。两轮反转版本顺序，每版每轮预热一次、采样四次。每次均产生两个断片。十步物理总耗时中位数为 310.5 / 319.0 ms，单步 P95 为 202.5 / 156.9 ms，帧间隔 P95 为 350.0 / 333.3 ms。CPU 渲染提交 P95 为 4.1 / 7.0 ms，主线程长任务共 88 / 89 个，资源峰值估算为 16.8 / 17.7 MiB。

稳定风洞的 Node 复测在 10 m/s 后采样三组 90 步。PR 为 152–165 ms，候选为 365–379 ms。候选约 71% 的 CPU 采样落在形变净空约束调用栈，其中约 64% 落在实体相交检查调用栈。同一翼段的固定和可动实体是较重的候选对。沿现有弦向增加快速分离检查的试验未改善该负载，已撤回。

### 稳定风洞遮蔽筛选

当前 PR 的机身表面遮蔽先按机身包围盒与翼段检测球筛选候选，再沿用原来的逐点翼型检验。用 Node 24.22.1 在 10 m/s 稳定风洞中对比 `d6669ba`，每次预跑 240 步，随后测三组各 90 步，步长 1/60 s。两轮反转版本顺序，90 步耗时中位数从 166.33 ms 降至 122.00 ms、从 182.28 ms 降至 114.95 ms。采样末态的结构节点、翼段遮蔽比例、应力利用率和能量逐值一致。

隔离的实体分区候选另在 `5ad7dd5` 中先识别表面接缝点，省去这些点的内部射线查询。同样的两轮风洞采样中，90 步耗时中位数从 539.59 ms 降至 490.99 ms、从 536.57 ms 降至 385.03 ms。风洞采样末态与四个触地场景的物理输出一致。此改动仅在隔离分支验证，现有数据仍显示候选的稳定风洞耗时高于 PR 实现。

实体分区候选对机身面片使用实际三角形重心的包围范围进行翼段粗筛，保留原遮蔽判定。与 `5ad7dd5` 对比，两轮反转顺序的稳定风洞 90 步中位数分别为 383.57 → 381.49 ms 和 411.23 → 341.82 ms。风洞末态的结构节点、翼段遮蔽比例、应力利用率和能量逐值一致，四个固定 60 Hz 触地场景的物理输出一致。两轮收益幅度差异较大，候选仍未达到当前 PR 的稳定风洞水平。
