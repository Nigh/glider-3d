# 长机翼触地计算

PR #52 的长翼触地瓶颈有三处：各连接重复扫描外侧翼段累计载荷、每个独立断片反复扫描整机接触点，以及接触形变二分时每次重算整机接触。现在局部载荷沿实际支撑树反向累计；翼段归属索引用于碎片质量、气动和碰撞；不可变接触索引用于按翼段或支撑分支同步和查询。垂尾支撑分支包含安装其上的平尾，限制形变时仍检查完整连接包络。

没有减少碰撞采样、积分精度或形变二分次数。每个接受步仍核对机械能与真实外力功，接触应力不因形变约束而被钳制。动态归属索引随分离和重置更新，回放恢复校验它与所有翼段的实际归属完全一致；静态数值索引由可信构造器重建。

## 同机测量

2026-11-10，Windows x64、Node v24.19.0，通过 Vite SSR 运行真实 `FlightSimulation.step()`。基线为 `65737ca`，依次测量基线与更新版本，没有同时运行浏览器或测试套件。每个场景为 24 m 翼展、3047 个整机接触点、60 Hz 下的 10 帧；一次预热、三次正式采样，取中位数。原始采样及轨迹/能量结果保存在 [contact-performance-results.json](contact-performance-results.json)。

| 场景 | 基线耗时中位数 | 更新耗时中位数 | 减少 | 末帧碎片数 |
|---|---:|---:|---:|---:|
| 小滚转触地断裂 | 967.18 ms | 815.29 ms | 15.7% | 26 |
| 较大滚转触地断裂 | 755.95 ms | 572.23 ms | 24.3% | 27 |
| 加粗梁完整长翼触地 | 1045.11 ms | 703.27 ms | 32.7% | 0 |

两版末帧位置保持数值精度内一致，能量账本相对误差约 `1e-15`。采样有运行时优化和机器负载波动，单次耗时见原始数据；这些是本地 Node 物理工作负载结果，不能用作浏览器帧率或真实手机性能结论。极端长翼接触仍然昂贵，分离片体的真实独立积分和密集接触约束仍需计算。

## 复现

在安装依赖的仓库运行 `node scripts/contact-performance.mjs`。要同机比较两个已安装依赖的 checkout，运行 `node scripts/contact-performance.mjs <baseline-checkout> <updated-checkout>`，输出为 JSON。脚本对每次测量检查能量账本相对误差小于 `1e-8`，记录接触点数、帧数、碎片数及最终位置；应串行测量，避免其他重型任务争用 CPU。
