# 固定60Hz长机翼触地

## 当前模型：v16

`fixed60-accumulated-fracture-v16` 保留准静态梁、参考质量、逐次卸载与0.25 rad累计形状预算。游戏物理固定60Hz，渲染自动插值；每个渲染帧允许8 ms物理追赶预算，至少执行一个到期步，超预算丢弃整tick积压、保留插值余量。性能不足时游戏时间变慢，不扩大物理dt。

每个有效连接在强度利用率 `r >= 1` 时，每tick累积 `min(1,max(0.2,r/5))`，到1且当前仍超限才断。恒定利用率1、1.5、2、3、5分别需5、4、3、2、1步；卸载低于1清零。递归接触、同tick重测及卸载重算只贡献一次tick峰值，不靠调用次数提前断裂。该规则是游戏失效延迟，不是材料疲劳。

只在累积成熟且真实超载的连接中选择当前最危险者，断后按新归属重算冻结外载与内部支撑载荷。新碎片不重复推进本步时间或应用冲量。原始应力不受几何上限钳制，T尾仍按实际支撑树处理。

## 真实程序测量

Linux x64、Node v24.9.0，Vite SSR运行真实 `FlightSimulation.step()`。基础单发型、24 m主翼、材料量2、初始x=50/z=100、速度 `(8,-0.3,0) m/s`；按接触包络放到地形上方1e-6 m。强梁截面为 `{ width: 0.15, height: 0.3, wallThickness: 0.005 }`。固定60Hz推进1/6 s，一次预热、三次采样，串行执行。

| 场景 | 中位耗时 ms | 碎片数 | 最大能量账本相对误差 |
|---|---:|---:|---:|
| 滚转0.08，弱梁 | 54.48 | 2 | 1.08e-15 |
| 滚转0.4，弱梁 | 52.54 | 3 | 6.15e-16 |
| 滚转0.08，强梁 | 124.80 | 0 | 1.18e-16 |
| 滚转0.4，强梁 | 124.37 | 0 | 6.70e-16 |

所有场景形状预算有效，强梁不分离；强梁最大垂直穿透分别为1.9883625910210867e-6 m、1.998428729166335e-6 m，未超2e-6 m。每次断裂都有重新测量、当前归属、成熟累积的证据。完整事件、耗时和末位置保存在 [contact-performance-results.json](contact-performance-results.json)。这些是Node工作负载结果，不是浏览器帧率或真机性能结论。

## 验收范围

- `node scripts/contact-performance.mjs`：固定60Hz四个真实场景，检查成熟断裂、逐次卸载、形状预算、净空、接触耗散与机械能，输出JSON。可传其他已安装依赖的checkout路径；需串行运行。
- `npm test -- --maxWorkers=1 --silent --testTimeout=30000`：392通过。覆盖30/60/144Hz时钟、30/60/120/240Hz渲染节奏驱动同60Hz真实碰撞的一致性、超预算减速、1至5步累积、同tick去重、卸载清零、镜像、纯分离守恒与回放状态。
- `tests/review-52.spec.ts`：真实物理长翼、组合T尾网格、关键帧恢复和双向seek，使用配置中的桌面与手机横竖视口。截图保存在Playwright输出目录。

长期平台接触回归额外发现：已有活动接触曾被扫掠无条件跳过，新的失效时序下可继续进入平台。现在仍对活动接触的新增穿透做接受步细分，不抬升或瞬移刚体，不修改容差或能量账本。

## 不再采用的旧验收

v15曾要求不同物理频率间的断裂拓扑和位置收敛；滚转0.08 rad时120/240Hz主体质心位置差0.6494612773422419 m。同checkpoint分叉证实准静态中点载荷会漏采短暂超限，不是旧冲量重复使用。

用户现选择固定60Hz和连续超限累积，旧跨物理频率断言已替换为“不同渲染节奏、相同固定物理tick”的一致性检查。这不是证明原模型跨频率收敛，也不是真实冲击传播求解。低级可变dt接口仅保留作诊断，游戏不切换物理频率。旧版26/27片同批切断结果不作为正确性基准。
